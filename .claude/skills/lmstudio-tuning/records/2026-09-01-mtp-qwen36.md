# 2026-09-01 — MTP re-test with a quant that ships the MTP head (Qwen3.6-35B-A3B GGUF)

Task T59. The first pass (`2026-09-01-first-pass.md`) showed `--speculative-draft-mtp` was a
silent no-op on the MLX 4bit `qwen3.8-27b` (no MTP head in that conversion). This record uses a
GGUF that does ship the head: `unsloth/Qwen3.6-35B-A3B-MTP-GGUF` UD-Q4_K_M (21.1 GB), served
by llama.cpp Metal 2.31.2 on the M3 Ultra. After `lms import` LM Studio lists it as `qwen3.6-35b-a3b-mtp`.

## Hypotheses

1. With a real MTP head, `--speculative-draft-mtp` lifts decode tok/s on low-entropy
   code/JSON output (agent-turn, kg-extract).
2. `--parallel 1` helps MTP (it optimises single-stream latency).
3. Qwen3.6-35B-A3B is at least as fast as the current default (Qwen3.5-35B-A3B Q4_K_M).

## Configs (all: `-c 131072`, `reasoning_effort:"none"`, temp 0, nonce'd prompts, 3 warm runs)

| key | load flags |
|---|---|
| A | `--parallel 4` |
| B | `--parallel 4 --speculative-draft-mtp` |
| C | `--parallel 1` |
| D | `--parallel 1 --speculative-draft-mtp` |

qwen3-coder-30b MLX decode 90.

## Findings

- **MTP engages but does not pay on llama.cpp Metal.** The head is real (the server log now prints
  `draft acceptance = 0.86 (189 accepted / 219 generated)`), acceptance is excellent, and decode
  is unchanged within noise (+1%, −1%). Hypothesis 1 rejected for this engine. This matches the
  field reports that speculative gains on Apple Silicon come through MLX, not llama.cpp Metal.
  With ~3B active parameters the verification pass costs about what the drafted tokens save.
- **`--parallel 1` changes nothing** for a single stream (C ≈ A, D ≈ B). Hypothesis 2 rejected.
  Keep `--parallel 4` so CCR sub-agents can fan out.
- **Qwen3.6-35B-A3B decodes ~35–45% faster than the 3.5 default** (105–114 vs 78 tok/s) at the
  same prefill and the same RAM (21 GB). Hypothesis 3 confirmed, and then some. Part of this may be
  Unsloth's UD quant rather than the model generation; an apples-to-apples 3.5 UD quant would
  separate the two.
- Quality (0–3 rubric, 12 agent-turn + 6 kg-extract runs):
  - agent-turn: valid `{tool, args}` JSON with a correct `--json` patch in 12/12; 11/12 append two
    sentences of prose after the JSON (the prompt allows it). Score 11/12 (format −1 for prose after
    JSON vs 3.5's pure JSON). Uses `args` where 3.5 uses `arguments`; consistent within the model.
  - kg-extract: 8–9 relations, evidence verbatim in 7–9 of them, `competes_with` found in 3/6 runs,
    one run invented composite entities ("Trino-based tooling", "Stockholm office"). Score ~8/9,
    on par with 3.5 and coder-30b; the same recall/verbatim trade-off, run-to-run variance higher.

## Decision

- **Do not enable `--speculative-draft-mtp`** on GGUF/llama.cpp loads. Revisit only with an MLX
  conversion that carries the MTP head, or after an LM Studio llama.cpp engine release that
  advertises MTP speedups.
- **Now the CCR default: `qwen3.6-35b-a3b-mtp`** (switched 2026-09-02, T61) (loaded *without* MTP). ~40% faster decode,
  same RAM, same-or-better quality on the two fixed prompts. Not switched in this pass because the
  default is user-facing (CCR router + warm-model LaunchAgent + skill docs all name the model).
  Applied: `WARM_MODEL` default in `warm-model.sh` → 3.6 (redeployed on the Studio); added to the
  `lmstudio` provider `models` (first) with `Router.default` and `Router.fallback.models` set to it.
  Server routing verified (explicit `--model` → 3.6 in the Studio log). **Caveat:** with gateway
  model discovery on, an interactive client's default is a client-side pick that bypasses
  `Router.default`; set it once with `/model` (3.6 is now first). See `claude-studio-launch`.

## Gotchas learned

- `lms get user/repo@quant` only resolves LM Studio catalog artifacts; a raw HF repo needs
  `curl -L -C -` and then **`lms import <file> --user-repo user/repo -y`**. A file placed by hand
  under `~/.lmstudio/models/user/repo/` is *not* indexed until imported. The first `lms import` on
  a machine shows a one-time "Do you wish to continue?" prompt that `--yes` does **not** answer:
  pipe `Y` and use `ssh -tt`.
- Server log lines `draft acceptance = …` are the only speculative-decoding telemetry; the
  `/api/v0` stats do not expose it.
